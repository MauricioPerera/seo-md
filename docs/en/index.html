The problem with AI and SEO

Telling a model "keep it short, use these keywords, don't mention that" doesn't work well. One of two things happens:

It over-repeats

If a check demands a keyword "must appear," the copy ends up repeating it unnaturally — what SEO people call keyword stuffing.

It sounds off

Ban a word without context and the AI dances around it with clunky phrasing — just to avoid tripping a badly designed check.

Nobody checks it

Without an automated way to verify, every title and description needs a manual review — which doesn't scale with how much content AI can produce.

How it works

SEO.md separates two very different kinds of rules, and treats them differently on purpose.

Limits that can't be crossed

Objective things: a title can't exceed a certain length, a keyword can't repeat more than X times. These get checked by a script, automatically — anything over the line gets fixed before it ships.

Style guidance

Things that need judgment: who the content is for, what tone to use, what story to tell. This gets explained to the AI in plain prose — never forced through an automated check, because forcing it is exactly what breaks the quality.

Who is this for?

Anyone using AI to write web content who wants a baseline of guaranteed quality — without reviewing every line by hand.

Marketing teams

Define your rules once (title length, keywords, tone) and any AI agent respects them afterward, without repeating the instructions every time.

Developers

A plain text file plus a script that runs in any project — no heavy libraries, no complex setup.

Agencies

One protocol across every client, with its own rules per project — consistency without losing what makes each brand different.

Open, free, and ready to try

The full protocol, a working example, and a real-world use case all live on GitHub.
